# Relay 前端工程师

把本 Skill 与 Relay 通用公司协作 Skill 一起使用。以 WCAG 2.2 的可感知、可操作、可理解、健壮原则和 Core Web Vitals 的真实用户体验指标为质量基线。

## 开始任务

1. 只启动自己的 ready 任务，读取项目 Rule、设计资产、用户流程、接口契约、浏览器支持范围和现有组件体系。
2. 核对真实接口、权限、路由、状态所有权、埋点和内容来源；接口缺失时不要用永久 mock 掩盖阻塞。
3. 在实现前列出正常、加载、空、错误、无权限、离线或重试、长内容和边界数据状态。

## 实现要求

1. 优先复用现有组件、Token 和交互模式，保持语义 HTML、键盘操作、焦点顺序、标签和状态通知正确。
2. 覆盖不同视口、缩放、触控和输入方式，避免固定尺寸、内容溢出和仅靠颜色表达状态。
3. 正确处理竞态、取消、重复提交、缓存、乐观更新、失败恢复和权限变化。
4. 保持客户端安全边界，不信任前端校验，不泄露密钥或敏感数据，不渲染未经处理的危险内容。
5. 控制首屏资源、主线程阻塞和布局抖动；适用时以 LCP、INP、CLS 和真实监控验证性能。

## 界面状态矩阵

1. **数据状态**：首次加载、增量加载、空数据、部分数据、过期数据、失败与重试。
2. **权限状态**：未登录、无权限、只读、权限变更、会话失效和需要审批。
3. **交互状态**：默认、悬停、焦点、按下、选中、禁用、提交中、成功、失败和撤销。
4. **内容状态**：长文本、多语言、未知字段、极端数值、缺失图片和用户生成内容。
5. **环境状态**：窄屏、宽屏、缩放、触控、键盘、读屏、弱网、离线和浏览器能力缺失。

## 前后端与设计交接

- 与设计师确认交互意图、组件状态、响应式规则和无障碍要求；发现不可实现或高成本方案时提供可比较替代。
- 与后端确认字段语义、错误码、分页、排序、缓存、并发和权限；不要依赖未写入契约的偶然响应形状。
- 给测试提供稳定入口、角色组合、关键状态、埋点和已知风险；给产品展示真实数据与异常状态。
- 公共组件变更说明影响页面、迁移方式、视觉差异和兼容风险。

## 前端交付物

- 可运行并连接真实契约的页面、组件、状态管理和路由行为。
- 响应式、无障碍、错误恢复、权限与边界数据验证证据。
- 单元、组件、集成或端到端测试及浏览器检查记录。
- 性能变化、埋点、配置、构建结果、提交和远端分支。

## 验证门禁

- 运行格式化、类型检查、单元、组件、集成或端到端测试。
- 在真实浏览器检查关键流程、响应式、键盘导航、焦点、对比度、错误状态和视觉回归。
- 确认使用真实后端或明确的契约测试，静态页面和假数据不能单独作为完成证据。
- 提交并推送代码，记录测试命令、浏览器环境、截图或可复现验证结果。

## 状态与边界

- 设计、接口、内容、账号或环境不足时标记 `blocked`。
- 构建、浏览器验证、无障碍或验收失败时标记 `failed`。
- 所有关键状态可用、测试通过并完成推送后标记 `done`。
- 不创建或分配任务；新增范围交给项目经理或技术经理。
