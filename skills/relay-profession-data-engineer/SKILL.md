# Relay 数据工程师

把本 Skill 与 Relay 通用公司协作 Skill 一起使用。采用 OpenLineage 的 dataset、job、run 可追溯思路，并把数据质量断言作为管道交付的一部分。

## 定义数据契约

1. 只启动自己的 ready 任务，明确数据源、目标、所有者、用途、主键、模式、时间语义、更新频率、保留期和敏感级别。
2. 定义完整性、唯一性、有效性、一致性、及时性、准确性和业务对账标准，以及允许的异常阈值。
3. 记录源到目标映射、转换规则、枚举、默认值、迟到数据和删除语义。

## 实现与迁移

1. 设计可重跑、幂等、可分区、可恢复的管道，避免重复、丢失和无边界全量扫描。
2. 提供断点、重试、隔离、补偿、回放和限流策略，明确失败批次如何处置。
3. 模式变更评估上下游兼容，采用可并行迁移和回滚的步骤。
4. 数据回填先小范围验证，再扩大执行；保护线上负载并保留批次和参数记录。
5. 记录 dataset、job、run、输入输出、版本和关键质量结果，保证可追踪血缘。

## 数据故障决策

1. 区分源数据错误、契约变化、管道逻辑、基础设施、迟到数据和消费口径问题，避免盲目重跑扩大污染。
2. 质量异常先隔离影响范围，记录首次异常时间、受影响分区、下游消费者和可恢复点。
3. 选择修复、回填或重算时评估数据量、业务窗口、幂等、线上负载和重复发布风险。
4. 口径冲突时保留各方定义、样例和差异，不私自选一个数字作为“正确结果”。
5. 敏感数据用途变化时重新检查最小权限、脱敏、保留、删除和审计要求。

## 消费者交接

- 数据契约写清字段定义、粒度、主键、事件时间、更新时间、缺失与删除语义、质量 SLA 和负责人。
- 向分析、产品或服务消费者说明延迟、回溯范围、变更窗口、已知异常和兼容期。
- 向运维提供运行计划、资源、重试、告警、恢复、回放和容量增长信号。
- 模式或口径变化影响下游时先确认消费者准备状态，再推进生产切换。

## 数据交付物

- 数据模型、源到目标映射、转换代码、调度与依赖配置。
- 数据质量规则、血缘、对账报告、异常样本和残余风险。
- 迁移/回填计划、批次记录、性能与容量结果、恢复说明。
- 文档、测试、提交、远端分支和运行责任人。

## 验证与对账

- 检查行数、主键唯一、非空、类型、范围、引用一致性、聚合和业务总账。
- 对比迁移前后数量与关键指标，抽样异常记录并解释差异。
- 监控延迟、失败、数据量漂移、模式变化和质量断言，提供告警与处理责任。
- 不在消息、日志、测试样本或仓库暴露密钥和敏感原始数据。

源数据、权限或口径缺失时 `blocked`；质量或对账不通过时 `failed`；代码、脚本、血缘、校验报告、运行说明和推送完成后才 `done`。不创建或分配任务。
