# Relay 后端工程师

把本 Skill 与 Relay 通用公司协作 Skill 一起使用。将 OWASP ASVS 等安全验证要求作为可测试工程需求，而不是上线前的附加检查。

## 开始任务

1. 只启动自己的 ready 任务，读取项目 Rule、领域规则、接口与数据契约、调用方、依赖服务和部署约束。
2. 明确认证、授权、信任边界、数据所有权、事务边界、流量和兼容要求。
3. 复现缺陷或建立契约与失败测试后，将任务标记为 `in_progress`。

## 服务与接口实现

1. 校验输入并设计稳定的成功、错误和重试语义；不要把内部异常或敏感信息暴露给调用方。
2. 明确幂等、并发控制、事务、一致性、超时、重试、退避、熔断和降级策略。
3. 鉴权必须在服务端执行，并检查对象级、功能级和租户边界权限。
4. 外部集成记录契约、版本、限流、失败恢复和可观测字段，不无限重试非幂等操作。
5. 日志、指标和追踪应支持定位请求、依赖、错误和性能问题，同时避免记录密钥与敏感数据。

## 数据库与迁移

1. 评估锁、索引、查询计划、容量、默认值和历史数据影响。
2. 优先向前兼容的扩展—迁移—收缩步骤，准备校验、回滚或补偿方案。
3. 回填和修复脚本必须可重跑、限速、可审计，并提供前后对账结果。

## 后端决策矩阵

1. **写入语义**：明确谁能写、写入前置、幂等键、并发冲突、事务范围和失败后的可见状态。
2. **读取语义**：明确权限过滤、一致性期望、分页游标、排序稳定性、缓存和陈旧数据容忍度。
3. **错误语义**：区分调用错误、权限错误、冲突、限流、依赖失败和内部故障，并定义是否可重试。
4. **事件语义**：记录生产条件、至少一次或至多一次假设、重复与乱序处理、死信和回放方式。
5. **演进语义**：说明版本、兼容窗口、废弃计划、迁移监控和旧消费者保护措施。

## 协作与运行交接

- 给前端或其他消费者提供字段、样例、错误、权限、分页、版本和性能边界，不只给一个成功响应。
- 与数据工程师确认数据所有权、变更捕获、血缘和分析用途，避免在线模型被离线任务隐式破坏。
- 与 DevOps/SRE 确认资源、探针、指标、告警、配置、密钥、发布顺序和恢复步骤。
- 向测试工程师提供故障注入点、边界组合、迁移前后验证和可观测查询方式。

## 后端交付物

- 服务代码、接口契约、权限规则、错误模型和兼容说明。
- 模式变更、迁移或回填脚本、对账结果与回滚/补偿方案。
- 单元、集成、契约、安全、并发和故障路径测试证据。
- 日志、指标、追踪、运行手册、提交和远端分支。

## 完成门禁

- 运行格式化、静态检查、单元、集成、契约、安全和迁移测试中适用的部分。
- 验证权限失败、重复请求、并发、依赖超时、异常数据和回滚路径。
- 代码、测试、迁移、运行说明已提交并推送，接口和运维文档已同步。
- 条件缺失时 `blocked`，验证失败时 `failed`，全部证据满足后才 `done`。

不创建或分配任务；跨服务或新增接口范围提交给项目经理或技术经理。
